# Tied Vote Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The result shows every value sharing the most votes, instead of one picked by JavaScript's key order.

**Architecture:** A pure function beside `resultColumns` turns the deck and the summary into the whole headline (label, tied set, figure, sub line, spoken figure). `Result` lays it out and marks the tied set's columns red. The e2e checks ride the existing session journey.

**Tech Stack:** React 19 + TypeScript 5.9, Vitest, Playwright (Chromium and Firefox).

**Spec:** `docs/superpowers/specs/2026-11-05-tied-vote-design.md`

## Global Constraints

- Headline per tied set: empty → label `Nobody voted`, nothing else; 1 → `Most voted`, figure `8`, sub `4 of 7 votes`, spoken `8`; 2 or 3 → `Most voted`, figure `5 · 8`, sub `Tied, 3 votes each`, spoken `5 and 8` / `3, 5 and 13`; 4 or more → `Most voted`, figure `Tie`, sub `<tied set size> values, k votes each`, spoken `Tie`.
- "vote" is singular when the count it follows is 1: `Tied, 1 vote each`, `13 values, 1 vote each`, `1 of 1 vote`.
- The list separator is space, U+00B7 middle dot, space: `' · '`.
- Tied set order is chart order (`resultColumns`' column order).
- Each drawn value goes through `Figure`. A list of two or three uses the existing `result-figure-list` class.
- The drawn figure is `aria-hidden`, and a `visually-hidden` sibling outside it holds the spoken figure.
- Every column whose value is in the tied set gets `result-column-top`.
- The summary's sort in `applySnapshot` stays.
- Comments: one or two lines each.

## Rulings

These are the choices the spec left open. Each names the simpler alternative and why it lost, or why it won.

1. **Shape.** `figure` is a `string[]` drawn one by one through `Figure`: `['8']`, `['5', '8']`, `['Tie']`, or `[]` for nobody. The simpler alternative is one joined string, but it cannot route `0.5` through `Figure`.
2. **Top count.** Both the function and `Result`'s bar share read it from `summary[0]`, as today, because `applySnapshot` sorts the summary by count and that sort stays. Computing `Math.max` would guard against an order the code guarantees. Returning a `top` field would change the return list the spec fixed.
3. **Plurals.** The single-winner line counts all votes cast. The tie lines count k.
4. **Spoken figure.** It is a `<span className="visually-hidden">` placed right after the `most-voted` span, with no test id, because the contract finds it by text. It is absolutely positioned, so it takes no cell in the narrow grid.
5. **Red marking.** `head.tied.includes(value)`. A `Set` would be no faster at 13 columns.
6. **Session checks.** Entries are picked with `nth` in chart order (`3`, `5`; then `5`, `8`). The alternative was a per-value locator helper, but the unit test already pins chart order.
7. **The 320 case.** Dropped while building (spec decision 7): a tied list at `--text-3xl` still fits at 320, so neither planned mutation turned the case red.
8. **1280 measurement.** A throwaway case, never committed, using 13 pageless voters. It reads one `tally-entry` width and takes a screenshot for the single `13`, for `0.5 · 13 · 89`, and for `Tie` over `13 values, 1 vote each`, *Flagged addition:* it also screenshots the `Tie` reveal at 320 (Review Focus 2), the one look at the longest sub line on the narrowest screen. The numbers and screenshots go to the user whatever they show. Measuring on the mockup was simpler, but it has no 13-way case.
9. **Stale comments.** The replacement texts are in Task 2, Step 7.
10. **Mockup.** `room.html` keeps its `tie3` and `tie4` vote sets, which now show the shipped rule in the default view. `later=1` no longer changes the result.
11. **Delivery.** One PR, with the docs folded into the code change. Commits follow the tasks.

## Review Focus

1. Three tied values at 320: the spoken span and the sub line must not make the page scroll sideways. Not a new read: the spoken span is short, absolutely placed text, and no plausible break of this change scrolls the page; the existing "no page scrolls sideways, 320 by 640" case covers the layout.
2. `Tie` over `13 values, 1 vote each` at 320: the label and the sub line must share their row without crushing each other or the figure. Covered by the Task 2, Step 6 screenshot, which comes back to the user. It is not a committed case.
3. A tied `0.5` keeps its tight point and reads `0.5` in `most-voted`. Not covered by a committed read: `Figure` keeps the text `0.5`, so a text read cannot see a lost tight point, and a break would be cosmetic.
4. Nobody voted shows the label only, with no stray spoken text or empty sub line. Test: Task 1's `nobody` case pins `figure: []` and `Result` draws nothing more when `figure` is empty. The existing `Nobody voted` e2e reads (`room.spec.js`, `layout.spec.js`) still pass.
5. A re-vote that turns a tie into a single winner drops red from the losing column. Test: Task 2, Step 3 (majority reveal, the `8` entry has no `result-column-top`).
