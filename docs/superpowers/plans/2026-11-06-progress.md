# Progress Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** While a round is open, the facilitator's slot shows who still has to vote, and a voter's table heading shows the count.

**Architecture:** A pure function turns the voters into the count, the bar and the name lines; a pure selector picks each line's text from its candidates. A hook measures the candidates in a scratch node and lets React draw the winner before paint. `RoundPanel` gives the facilitator's slot the panel while voting, so the table's reserve for that slot goes.

**Tech Stack:** React 19 + TypeScript 5.9, Vitest, Playwright (Chromium and Firefox).

**Spec:** `docs/superpowers/specs/2026-11-06-progress-design.md`

## Global Constraints

- Copy, exactly: `4 of 6 voted`, `No vote: `, `Not confirmed: `, `and N more`, `Everybody voted`, `No voters yet`, `Voters · 4 of 6 voted`, region name `Progress`, roster pill `No vote`.
- "Voted" is `voteState(u) === 'confirmed'` everywhere; kept cards are not counted.
- Names in table order: the order of `view.users`.
- The count at `--text-xl`, weight 700; name lines at `--text-lg`, label at `--weight-strong`. The bar is `aria-hidden`.
- Component CSS takes no px (the gate's `literalProblems`, 4c1-foundation) and, by convention, no literal rem: lengths are tokens.
- Browser cases run through `npm run e2e`, whose `pree2e` builds and stages the app; `npx playwright test` tests a stale build.
- No live region and no tab stop on the panel.
- Names are user input: the scratch node is built with `textContent`, never `innerHTML`.
- Comments: one or two lines each.

## Rulings

These are the choices the spec left open. Each names the simpler alternative and why it lost, or why it won.

1. **Task order.** The handoff wanted the fit hook built and browser-tested before the panel. The only element that draws a name line is the panel, and the panel in the slot cannot land without the reserve going (both would hold the slot's room, so 'no scroll at the floor' fails). So Task 1 is the pure logic, the fit selector included. Task 2 builds the hook first, then the panel around it, the reserve's removal and the layout restatement. Task 2 is judged as one piece: the facilitator's slot while voting. The alternative was a throwaway harness page for the hook, which is test infrastructure the app does not have.
2. **`progress` returns `null` for no voters.** Otherwise it returns `{ voted, total, bar, lines }`, and `lines: []` means everybody voted. The component holds the copy `Everybody voted` and `No voters yet`. The alternative, a tagged union with a `kind`, has three cases where `null` and an empty list already say it.
3. **Callers pass the voters.** Both `Voters` and `RoundPanel` filter `view.users` by `!u.facilitator`, as `Voters` does today. The heading takes its count from `progress()`, so the panel and the heading can never disagree.
4. **The fit's pure half lives in `room/fit.ts`**, beside `largestFit`, tested in `fit.test.ts`. The selector never measures the last candidate, the count: it is returned unconditionally.
5. **The scratch node copies the line's computed font longhands.** The list is `fontFamily`, `fontSize`, `fontStyle`, `fontWeight`, `fontStretch`, `fontVariant`, `fontFeatureSettings`, `fontVariationSettings`, `fontKerning`, `letterSpacing`, `wordSpacing` and `textTransform`. Its `<b>` copies the drawn `<b>`'s computed `fontWeight`; a bare `<b>` in the body would be 700, not 600. The shorthand `font` was simpler, but its computed serialisation is not guaranteed in Firefox. The node sits in `document.body`, `position: absolute`, `visibility: hidden`, `white-space: nowrap`, `width: max-content`, `aria-hidden`. It is compared with the line's `getBoundingClientRect().width` less its horizontal padding. `clientWidth` rounds, so it was set aside.
6. **One `NameLine` component per line, keyed by its label**, owns the hook. A line that changes label (line 2 moving up to line 1) remounts with that label's own state. Keying by index would also work, since the effect's synchronous update lands before paint; the label is the line's identity, so it is the key.
7. **Two new tokens for the bar.** The mockup's `3px` gap and kept frame and its `0.5rem` height break the gate's no-px rule and the tokens-only convention. The new tokens are `--progress-bar: 0.5rem` (the bar's height) and `--progress-band: max(2px, 0.1875rem)` (the segments' gap and the kept frame). Reusing `--frame-band` (6 px) would fill a kept segment at any size and change the accepted cost's 23-voter figure. *Flagged: the spec lists tokens going, not coming.*
8. **The phone sheet's height** uses the mockup's own selector, `.round-panel-slot:has(.progress) { height: auto; }`, inside the phone container query, so the app and `room.html` read the same.
9. **`keepClearOfSheet`** reads `.round-panel` alone and returns early when it is missing, folded into the existing `!bar` guard. TypeScript needs that guard; it decides nothing else.
10. **Browser cases go in a new `e2e/progress.spec.js`.** Restated cases stay where they are.
11. **The 860 by 600 run of "the entries' scale holds through a reveal".** The implementer reads `--s` with 4 voters at 860 by 600. If it is below the cap (`--deck-card` / `--entry-mark`), the viewport joins the case; if not, the case stays as it is and `nobodyVoted`'s read of Bob's slot covers it. The reading goes into the report either way.
12. **Delivery.** One PR on `20261106.progress-panel`, the docs folded in. Commits follow the tasks. The #497 note is drafted in Task 4 and shown in chat; it is posted only after the user's OK.

## Review Focus

1. A name that looks like markup (`<b>Zoe</b>`) is drawn and measured as text. A scratch node built with `innerHTML` would measure it short and draw an overflowing line. Pinned in Task 2, 'a name written as markup is measured as text'.
2. A name with an emoji falls back to another font in the drawn line and in the scratch node alike. Pinned in Task 2, the join case.
3. One unbroken 60-character name (`LONG_NAME`) at 320 and at 640 by 300: the facilitator's line falls to the count, and nothing scrolls sideways. Pinned in Task 2, 'no page scrolls sideways'.
4. A window that changes only in height changes the root size (J2's clamp) and the line's font; the line's own resize must refit it. Pinned in Task 2, the phone case.
5. The scratch node never outlives a fit: no `aria-hidden` node is left as a child of the body. Pinned in Task 2, the snapshot case.

Untested, safe in its direction: the scratch `<b>`'s copied weight. Without it a bare `<b>` measures at 700, wider than the drawn 600, so the fit only grows more cautious and never overflows.
